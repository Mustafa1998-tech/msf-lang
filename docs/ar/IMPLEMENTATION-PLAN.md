# MSF Lang 0.1 — خطة التنفيذ والاختبار

**المواصفات:** [`SPEC-v0.1.md`](SPEC-v0.1.md)، الإصدار `0.1.0-draft.1`
**الحالة:** مسودة للاعتماد. **لم يُكتب أي كود للمحرك ولم تُشغَّل أي اختبارات بعد.**
**بيئة الهدف:** C# 14 / .NET 10 (`net10.0`)، Windows أولًا، مع تصميم قابل للنقل.

## 1. ما الذي تُثبته هذه الخطة

كُتبت الخطة بحيث يمكن التحقق من كل ادعاء بأمر ونتيجة ملاحظة:

  والتاريخ وملخص النتيجة. وإلى أن يُملأ السطر، لا تُعد الميزة مكتملة.
- لا تُضاف ميزة خارج المواصفات المعتمدة دون سجل قرار جديد.

> **الدليل الحالي:** لا شيء. لا يوجد حل (Solution) ولا كود مصدري ولا مشروع اختبارات بعد.

## 3. عقود المكوّنات

### 3.1 `SourceText`

المسؤوليات:

- حمل مسار العرض والنص الأصلي.
- قبول BOM اختياري في البداية وإخفاؤه من النص.
- بناء فهرس بدايات الأسطر لـ LF وCRLF وCR.
- تحويل إزاحة محرف مطلقة إلى `SourcePosition` يبدأ من 1.
- حساب الأعمدة بقيم Unicode القياسية (`Rune`)، لا بوحدات UTF-16.
- إرجاع سطر المصدر لمقتطف التشخيص.

لا يحسب المعجم السطر والعمود بنفسه؛ يسجل الإزاحات ويسأل `SourceText`.

### 3.2 التشخيصات

`Diagnostic`:

```text
Code        string        // "E4002"
Phase       enum          // Lexical, Syntax, Semantic, Runtime, Cli, Io, Internal
Message     string
Span        TextSpan
Start       SourcePosition
Hint        string?
```

يرسم `DiagnosticFormatter` الصيغة الواردة في القسم 12.3 من المواصفات. وهو الكود الوحيد
المسموح له بتحديد التخطيط. تفحص الاختبارات الحقول البنيوية والنص المرسوم لمجموعة صغيرة من
التشخيصات الذهبية.

الاستثناءات:

- `LexException` و`SyntaxException` و`SemanticException` تحمل تشخيصًا واحدًا.
- `RuntimeException` يحمل تشخيصًا واحدًا.
- `InternalErrorException` ليس تشخيصًا لغويًا ويُحوَّل إلى الخروج 70.

لا تُحلَّل رسالة استثناء لاستعادة رمز. الرمز حقل صريح.

### 3.3 المعجم

العقد العام:

```csharp
IReadOnlyList<Token> Lex(SourceText source);
```

القواعد:

- تخطي الفراغات وتعليقات السطر وتعليقات الكتل غير المتداخلة.
- قبول BOM عند الإزاحة 0 فقط.
- تمييز الكلمات المحجوزة والمعرّفات بحساسية لحالة الأحرف.
- تمييز الأعداد العشرية مع جزء كسري اختياري؛ ورفض الأعداد غير المنتهية.
- تمييز النصوص والتهريبا الخمسة؛ رفض فواصل الأسطر الخام والتهريبا المجهولة.
- إصدار `EOF` بمدى صفري في النهاية.
- رمي `LexException` عند أول خطأ معجمي.

يحتوي `Token` على `Kind` و`Lexeme` وقيمة حرفية اختيارية و`TextSpan`. أنواع الرموز صريحة
(`Let`, `Var`, `Fn`, `If`, `Else`, `Return`, `True`, `False`, `Nil`, `And`, `Or`, `Not`,
`Identifier`, `Number`, `String`، علامات الترقيم، `Eof`).

### 3.4 شجرة التجريد

العقد العليا:

```text
Program        : Declaration[] 
Declaration    : FunctionDecl | VarDecl | Statement
Statement      : IfStmt | ReturnStmt | BlockStmt | AssignStmt | ExprStmt
Expression     : LiteralExpr | NameExpr | UnaryExpr | BinaryExpr | CallExpr | GroupingExpr
```

يحمل `FunctionDecl` رمز الاسم ورموز المعاملات وجسم الكتلة والمدى. ويحمل `VarDecl` خاصية
`IsMutable` ورمز الاسم والمُهيّئ والمدى. لكل عقدة `TextSpan`. الإسناد تعليمة وليس تعبيرًا.
يحمل `CallExpr` رمز اسم الدالة والوسائط؛ ولا يقبل تعبيرًا عشوائيًا كدالة مستدعاة.

### 3.5 المحلل النحوي

العقد العام:

```csharp
Program Parse(IReadOnlyList<Token> tokens);
```

التنفيذ:

- دالة واحدة لكل إنتاج نحوي، تسمى باسم الإنتاج.
- تحليل تعبيرات بطبقات مطابقة للقسم 4.2 من المواصفات.
- نظرة أمامية للإسناد: `IDENT` يليه `=` في بداية التعليمة.
- عندما يتبع تعبيرًا غير اسمي رمز `=`، رمي `E2011` عند `=`.
- تتبع عمق التداخل للتعبيرات والكتل وسلاسل `if`/`else`؛ وتطبيق الحد 256 (`E2013`).
- الإبلاغ دائمًا عن الرمز المخالف. وعند EOF، استخدام `E2010` لكل فشل في رمز متوقع.
- بناء مدىات تبدأ عند أول رمز وتنتهي عند نهاية آخر رمز مستهلك.
- رمي `SyntaxException` عند أول خطأ.

### 3.6 المحلل الدلالي

يجري المحلل الدلالي الفحوص الثابتة ويشرح العقد الحاملة للأسماء بارتباط `Binding`.

`Binding`:

```text
Id             int          // فريد طوال التشغيل/الجلسة
Name           string
Kind           Variable | Function | Builtin
IsMutable      bool         // للمتغيرات فقط
Arity          int?         // دوال المستخدم
Declaration    TextSpan
```

النطاقات:

- يحوي النطاق العام `print` (Builtin، متغير الوسائط).
- نطاق جسم الدالة يحتوي المعاملات والمتغيرات المحلية في المستوى الأعلى من الجسم. وليس
  نطاقًا فرعيًا إضافيًا لنطاق المعاملات.
- كل كتلة أخرى تنشئ نطاقًا فرعيًا.
- يُحلّ المُهيّئ قبل إعلان الارتباط الجديد.
- تُعلن دوال المستوى الأعلى في النطاق المحيط قبل حل أجسامها، فيعمل الاستدعاء الذاتي
  المباشر. لكنها ليست مرفوعة، فلا تكون الدوال اللاحقة مرئية.
- لا يجري المحلل استنتاج أنواع. أخطاء الأنواع وقت التشغيل.

الفحوص بترتيب الظهور:

| الرمز | الفحص | موضع الإبلاغ |
|---|---|---|
| `E3001` | الاسم غير موجود | رمز الاسم |
| `E3002` | إعلان مكرر في النطاق نفسه | رمز الاسم الثاني |
| `E3003` | معامل مكرر | رمز المعامل الثاني |
| `E3004` | إعلان باسم `print` | الاسم المعلن |
| `E3005` | إسناد إلى `let` | هدف الإسناد |
| `E3006` | إسناد إلى دالة/مدمجة | هدف الإسناد |
| `E3007` | `fn` خارج المستوى الأعلى | كلمة `fn` |
| `E3008` | عدم تطابق عدد الوسائط | اسم الدالة |
| `E3009` | استدعاء متغير | اسم الدالة |
| `E3010` | دالة/مدمجة في موضع قيمة | رمز الاسم |
| `E3011` | `return` خارج دالة | كلمة `return` |

يجب أن يستخدم المفسّر معرّفات الارتباط من المحلل الدلالي. ولا يجوز أن يبحث عن الأسماء
نصيًا وقت التشغيل، إلا في أدوات التنقيح.

### 3.7 المفسّر

العقد العام:

```csharp
RunResult Execute(Program program, SemanticModel model, TextWriter stdout);
```

- القيم: `MsfNumber` و`MsfString` و`MsfBoolean` و`MsfNil`، إضافة إلى قيم قابلة للاستدعاء
  داخلية.
- البيئة: `Dictionary<int, MsfValue>` مع مؤشر للأب. نطاقات الكتل أبناء؛ ونطاقات استدعاء
  الدوال أبوها النطاق العام.
- `let` يقيّم المُهيّئ ثم يعرّف الارتباط مرة واحدة.
- `var` يفعل الشيء نفسه ويسمح بالإسناد لاحقًا.
- الإسناد يقيّم الطرف الأيمن ثم يحدّث الارتباط.
- `if` يقيّم الشرط، ويشترط `boolean`، ثم ينفّذ فرعًا واحدًا.
- `return` يستخدم استثناء `ReturnSignal` داخليًا يُلتقط عند حدود الدالة فقط.
- استدعاء دالة المستخدم يفحص عداد العمق، ويربط الوسائط، وينفّذ الجسم، ويعيد `nil` إذا انتهى
  الجسم بلا `return`.
- `print` ينسّق كل وسيطة ويكتب سطرًا واحدًا، مع تفريغ المخزن.
- تُرفع E4001/E4002/E4003/E4004/E4005/E4006 بالمدى المحدد في المواصفات.
- تُفحص النتائج العددية بـ `double.IsFinite`.
- لا تتسرب استثناءات كأخطاء لغوية إلا `RuntimeException`؛ والعيوب الداخلية تصبح
  `InternalErrorException` بالخروج 70.

### 3.8 استراتيجية سلامة المكدس

يفرض المفسّر حدًا أقصى 1000 استدعاء مستخدم نشط، لكن المفسّر الشجري يستهلك إطارات مضيف
كثيرة لكل استدعاء لغوي. لجعل الحد آمنًا:

- يشغّل سطر الأوامر المحرك على `Thread` مخصّص بمكدس **32 MiB**.
- يستخدم مضيف الاختبارات مساعد الخيط نفسه لاختبارات عمق الاستدعاء وتشغيل المطابقة.
- يحدث فحص العمق قبل ربط الوسائط، فيفشل الاستدعاء 1001 بـ `E4005` بدل
  `StackOverflowException` في المضيف.
- اختبار يستدعي دالة ذاتيًا 1001 مرة ويتحقق من `E4005`؛ واختبار منفصل يؤكد نجاح 1000
  استدعاء متداخل.

هذا السلوك جزء من الخطة لا من سطح اللغة؛ اللغة تعد بحد 1000 استدعاء فقط.

### 3.9 سطر الأوامر

يعيد `Program.Main` رمز خروج. محلل الأوامر يدوي:

```text
args[0] == "run"       -> مسار واحد بالضبط
args[0] == "repl"      -> بلا معاملات إضافية
args[0] == "--help"    -> طباعة المساعدة، 0
args[0] == "-h"        -> طباعة المساعدة، 0
args[0] == "--version" -> طباعة "msf 0.1.0"، 0
args[0] == "-v"        -> طباعة "msf 0.1.0"، 0
غير ذلك                -> E5001/E5002، 3
```

`RunCommand`:

- قراءة UTF-8 صارمة باستخدام
  `new UTF8Encoding(encoderShouldEmitUTF8Identifier: false, throwOnInvalidBytes: true)`.
- التمييز بين `FileNotFoundException`/`DirectoryNotFoundException` (E5003) وأخطاء القراءة
  الأخرى (E5004) و`DecoderFallbackException` (E5005).
- ضبط `Console.Out.NewLine = "\n"` واستخدام مخرجات UTF-8.
- تنسيق التشخيصات إلى الخطأ القياسي؛ بلا ألوان.
- التشغيل على خيط المكدس المخصّص.
- ربط المراحل برموز الخروج 1 و2.

### 3.10 REPL

يملك `ReplSession`:

- `Scope` عامًا مستمرًا في المحلل الدلالي،
- `Environment` عامًا مستمرًا في المفسّر،
- عداد `Binding.Id` متزايدًا.

لكل مدخلة:

1. اقرأ الأسطر حتى تكتمل أو يُبلغ EOF.
2. خذ لقطة من النطاق العام والبيئة (نسخ سطحية للقواميس و`next ID`).
3. حلل المصدر المتراكم معجميًا ونحويًا ودلاليًا مع النطاق العام المستمر.
4. نفّذ.
5. عند خطأ ترجمة: اطبع التشخيص، ولا تستعد شيئًا (حل الأسماء معاملاتي: لا يغيّر إلا نسخة
   عمل، أو يطبّق الإعلانات بعد النجاح)، ثم أكمل.
6. عند خطأ تشغيل: اطبع التشخيص، واستعد اللقطة، ثم أكمل.
7. عند النجاح: ثبّت النطاق/البيئة الجديدة واطبع قيم العرض التلقائي.

يجب أن يكون المحلل الدلالي معاملاتيًا لمدخلات REPL. خطأ الترجمة لا يجوز أن يترك ارتباطًا
جزئيًا. أبسط تنفيذ هو الحل في نطاق عام مستنسخ واستبداله عند النجاح؛ وهذا رخيص في 0.1.

سلوك المطالبات واللافتة يتبع القسم 14 من المواصفات. الوضع غير التفاعلي سطري وبلا مطالبات،
ما يجعله قابلًا للاختبار بإعادة توجيه الإدخال.

### 3.11 الواجهة العامة

```csharp
public sealed record RunResult(
    int ExitCode,
    string StandardOutput,
    Diagnostic? Diagnostic);

public static class MsfEngine
{
    public static RunResult Run(SourceText source);
}
```

يجوز لسطر الأوامر استخدام حمولات (Overloads) تكتب مباشرة إلى `TextWriter`؛ ويستخدم مضيف
الاختبارات `StringWriter`. لا يحتوي `RunResult` على تتبّع مكدس أبدًا.

## 4. استراتيجية الاختبار

### 4.2 صيغة حالة المطابقة

لكل ملف `.msf` تحت `tests/conformance/` ملف مرافق بالاسم نفسه:

```text
tests/conformance/positive/arithmetic-precedence.msf
tests/conformance/positive/arithmetic-precedence.expected.json
```

```json
{
  "exitCode": 0,
  "stdout": "7\n9\n-1\n3.75\n",
  "diagnostic": null
}
```

لحالة خطأ:

```json
{
  "exitCode": 2,
  "stdout": "",
  "diagnostic": {
    "code": "E4002",
    "line": 7,
    "column": 14,
    "phase": "runtime"
  }
}
```

القواعد:

- `stdout` دقيق، بنهايات `\n`، ويُقارن كنص.
- `exitCode` إلزامي.
- `diagnostic` قيمته `null` عند النجاح.
- يفشل المضيف إذا وُجد `.msf` بلا ملف مرافق، أو ملف مرافق بلا `.msf`.
- الملف المرافق JSON بترميز UTF-8 بلا تعليقات.
- يشغّل مضيف المطابقة داخليًا ولا يفحص نص التشخيص الكامل؛ وتفحص اختبارات CLI الصيغة
  منفصلة.
- كل برنامج مطابقة برنامج MSF Lang صالح ومضمّن في المستودع.
- لا يجوز تخطي اختبار أو تعليمه "معلّقًا" في بوابة إصدار.

## 6. سيناريوهات تحقق سوداء الصندوق

هذه سيناريوهات يمكن للمراجع تشغيلها يدويًا بعد M8:

1. `msf run examples/hello.msf` → `Hello, MSF!` والخروج 0.
2. `msf run examples/factorial.msf` → `3628800` ثم `55` والخروج 0.
3. خطأ نوع وقت التشغيل → الخروج 2، تشخيص E4004، سطر/عمود صحيحان، بلا تتبّع مكدس.
4. إسناد إلى ثابت → الخروج 1، E3005، وبلا أي مخرجات من البرنامج.
5. ملف مفقود → الخروج 4، E5003، بلا انهيار.
6. REPL بأنبوب:
   ```text
   let x = 5;
   x * 2;
   fn square(n) { return n * n; }
   square(x);
   ```
   → `10` و`25`، الخروج 0، بلا مطالبات.
7. تراجع REPL: أعلن `var x = 1;`، ثم مدخلة تسند `x = 2;` وتقسم على صفر؛ بعد الخطأ،
   `x;` يعرض `1` لا `2`.
8. `msf --version` → بالضبط `msf 0.1.0`.
9. مسار يحتوي مسافات يعمل.
10. مخرجات نص عربي UTF-8 بلا تشويه.

إذا فشل أي سيناريو، لا يُقبل مرشح الإصدار مهما كان عدد اختبارات الوحدة.

## 7. المخاطر والتخفيف

| الخطر | الأثر | التخفيف |
|---|---|---|
| تجاوز مكدس المضيف قبل E4005 | انهيار العملية | خيط مكدس 32 MiB، فحص العمق، اختبار 1001 استدعاء |
| انحراف حالة REPL بعد خطأ تشغيل | نتائج خاطئة لاحقًا | لقطة/تراجع للنطاق والبيئة، اختبار C-20 |
| خطأ عمود Unicode | تشخيصات خاطئة | `SourceText` قائم على `Rune`، اختبارات عربية/رموز |
| تحويل Windows لنهايات الأسطر | فشل الاختبارات الذهبية | `\n` صريح، اختبارات بايتات خام لـ CLI |
| BOM أو ترميز غير متسق | تشويه ونقص E5005 | مفكك صارم، اختبار BOM، اختبار UTF-8 معاد التوجيه |
| اختلاف مسار العرض | اختبارات هشة | المسار كما هو، ومسار نسبي مضبوط في الاختبارات |
| غموض else أو الإسناد في المحلل | شجرة خاطئة | تنازلي تعاودي، اختبار else المعلّق، اختبار E2011 |
| انحراف تنسيق الأعداد | فروق ذهبية | `ValueFormatter` واحد، اختبارات `-0` والعلمي والكسري |
| توسع النطاق | تأخير وتناقض | تجميد 0.1، وأي ميزة تحتاج سجل قرار معتمد |
| ادعاء اختبارات بلا تشغيل | ثقة زائفة | `TEST-EVIDENCE.md`، ولا "مكتمل" بلا مخرج أمر |
| مفاجآت ألوان/ترميز CLI | لقطات غير حتمية | بلا ANSI في 0.1، واختبارات UTF-8 وLF |

## 8. تعريف الإنجاز في 0.1

تكون الميزة منجزة فقط عندما تتحقق كل الشروط:

1. سلوكها موصوف في وثيقتي اللغة.
2. لها اختبار وحدة واحد على الأقل، وحالة مطابقة `.msf` حيث يكون السلوك ملاحظًا.
3. شُغّل الاختبار فعلًا وسُجل أمره ومخرجاته.
4. لا تنتج تحذيرًا تحت `-warnaserror`.
5. لا تغيّر سلوكًا خارج المواصفات المعتمدة.
6. رمز تشخيصها وموضعهما مختبَران إذا كانت قابلة للفشل.
7. أمثلة التوثيق تستخدم السلوك المنفّذ وتُشغَّل خلال M8.

يكتمل الإصدار عند تحقق معايير خروج M0–M9، ونجاح المجموعة كاملة بلا تخطٍ، ونجاح
سيناريوهات القبول اليدوية.

## 9. مسار الهوية والتكامل (منفصل عن المحرك)

هذا المسار لا يعطّل المحرك، والمحرك لا يعطّله. وله بواباته الخاصة.

| المرحلة | العمل | البوابة |
|---|---|---|
| B0 | ثلاثة مفاهيم شعار + معاينة + مبررات | **البوابة B: يختار المالك مفهومًا** |
| B1 | الشعار النهائي (ملون/داكن/فاتح/أحادي)، أيقونة ملف مفصلة ومبسطة، أحجام PNG، ICO، صفحة معاينة | مراجعة بصرية وتقنية |
| B2 | إضافة VS Code: معرّف لغة `.msf`، قواعد TextMate، إعدادات اللغة، سمة أيقونات، وضعان فاتح/داكن | تثبيت واختبار في VS Code |
| B3 | مثبّت Windows: تثبيت لكل مستخدم، ربط `.msf` اختياري، ProgID، تنظيف عند الإزالة، فتح في VS Code | **البوابة D: موافقة صريحة قبل أي كتابة في السجل** |
| B4 | `BRAND_GUIDELINES.md`، بيان الأصول، ملاحظات اختبار التكامل | مراجعة نهائية |

تفعيل سمة أيقونات VS Code صريح: سمة الأيقونات المساهمة لا تظهر تلقائيًا. ستوثق الإضافة
اختيار **File Icon Theme → MSF Lang**، وقد توفر أمرًا يحدّث `workbench.iconTheme` فقط بعد
أن يستدعيه المستخدم. الإضافة تعريفية للإبراز، وتشغّل ملف `msf` الحقيقي للتنفيذ؛ ولا تفسّر
MSF Lang في JavaScript أو TypeScript.

سيُنفّذ تكامل Windows في المثبّت، لا عبر سكربتات سجل عشوائية أثناء التطوير. لا تُجرى أي
تغييرات في السجل في هذه المرحلة.
